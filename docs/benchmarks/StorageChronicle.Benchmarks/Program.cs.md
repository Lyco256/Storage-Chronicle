# Benchmarks/Program.cs

All benchmark suites use BenchmarkDotNet's out-of-process .NET CLI toolchain. The 1M Storage suite is isolated as its own matrix lane; in-process execution is intentionally not used because BenchmarkDotNet rejects the long-running 1M operation and cannot produce a valid report for it. The two external-media benchmark stores pass an explicit allow callback only for their exclusively created OS-temp fixture roots; this is benchmark fixture authorization, not product mirror consent or permission to write to monitored media.

Runs opt-in BenchmarkDotNet measurements for one-million MFT-like identities and one million streamed small storage records, a one-hundred-thousand-child folder move, and one-hundred-thousand grouped/Event Stack/diff/append/Zstandard/SQLite/media workloads. The central job uses one measured iteration with no warmup and `DontEnforcePowerPlan()` so benchmark invocation does not change the host power plan; this keeps the deterministic matrix bounded and does not claim statistical variance. It temporarily sets the process-only `UseArtifactsOutput=false` MSBuild property for BenchmarkDotNet's generated child build and restores the prior process environment afterward. Storage append streams the 1M fixture in real 512-event bounded canonical batches through immutable segments and coupled SQLite without retaining the full event set; the 100K suite also measures final Zstandard close and SQLite rebuild/query. Repository projects retain the conventional `bin`/`obj` layout even when BenchmarkDotNet supplies its own `ArtifactsPath`, avoiding SDK artifact-layout redirection in generated project-reference builds. Benchmark roots are created with exclusive Windows directory creation under the OS temp root; a GUID owner marker gates recursive cleanup, and reparse points or an out-of-bound path fail closed. The folder-move benchmark applies exactly one parent relationship event and verifies that no synthetic descendant events are created. Fixtures are deterministic and metadata-only; they are not a substitute for release hardware acceptance measurements. `MemoryDiagnoser` is enabled and JSON/Markdown output is produced by `build/quality/Test-Performance.ps1`.
