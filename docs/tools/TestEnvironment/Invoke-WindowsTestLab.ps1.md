# Invoke-WindowsTestLab.ps1

Orchestrates the selected Windows 11/Windows 10 TestLab stages after the user has approved the local config and passed `-Apply`. `-Target Windows11` does not require a Windows 10 ISO; `-Target Windows10` and `-Target Both` do. For each selected guest it restores the `SC-CLEAN-BASELINE`, creates and attaches one disposable role-specific VHDX, starts the VM, transfers the real workload executable over PowerShell Direct, formats and labels the guest data volume, creates both required marker files, executes the full metadata lifecycle workload for `Workload`/`NonNtfs` or the distributed zero-byte MFT workload for `Mft`, re-reads both guest markers before cleanup, retrieves the oracle, stops the VM, and detaches/deletes the exact VHDX. `Workload`, `Mft`, and `NonNtfs` roles select the required filesystem label and workload scenario. Every mutating stage is bounded to the approved TestLab root and a named TestLab VM; cleanup is refused when the current TestId/Role marker cannot be verified, and cleanup failures remain visible and prevent an acceptance claim.

The script records Explorer correlation as `NOT_EXECUTED` unless an independent human-assisted evidence file is supplied; it never synthesizes Explorer events or marks the final acceptance eligible. It does not install Hyper-V, reboot, download ISOs, touch physical host media, or treat a workload-only run as product/privileged acceptance: the manifest remains `AcceptanceEligible=false` until the real Agent, source/canonical/state, capability, and oracle checks are independently attached.
