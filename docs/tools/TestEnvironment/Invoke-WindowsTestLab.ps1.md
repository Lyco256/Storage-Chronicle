# Invoke-WindowsTestLab.ps1

Orchestrates the selected Windows 11/Windows 10 TestLab stages after the user has approved the local config and passed `-Apply`. `-Target Windows11` does not require a Windows 10 ISO; `-Target Windows10` and `-Target Both` do. For each selected guest it restores the `SC-CLEAN-BASELINE`, creates and attaches one disposable role-specific VHDX, starts the VM, transfers the complete workload publish directory over PowerShell Direct, formats and labels the guest data volume, creates both required marker files, executes the full metadata lifecycle workload for `Workload`/`NonNtfs`, the ACL-denied candidate workload for `AclDenied`, or the distributed zero-byte MFT workload for `Mft`, re-reads both guest markers before cleanup, retrieves the oracle, stops the VM, and detaches/deletes the exact VHDX. `Workload`, `Mft`, `NonNtfs`, and `AclDenied` roles select the required filesystem label and workload scenario. When `-GuestAgentExecutable` is supplied, its complete publish directory is transferred too; the guest receives an isolated machine-settings document, runs the real Agent with the dedicated non-diagnostic `--testlab` host mode against the marked root, stops it, retrieves its durable history, and invokes `StorageChronicle.RealIoOracleValidator` to compare Source Events, Canonical Events, and reconstructed State with the workload oracle. If `-ExplorerEvidencePath` is supplied for the Windows 11 run, the harness also writes a real TestLab correlation environment manifest and invokes `StorageChronicle.LiveCorrelationValidator`; `-CorrelationEvidencePath` selects its strict `StorageChronicle.AgentExplorerCorrelationEvidence.v1` output path. The manifest records `ExecutionMode=TestLab`, `AgentHostMode=TestLab`, and `Diagnostic=false`, and the final acceptance gate requires these fields. Supply a self-contained Windows publish directory (or single-file self-contained executable) for both guest programs; the harness does not install a .NET runtime in the guest. Without the Agent executable the manifest keeps an explicit `AgentIntegration-*` stage as `NOT_EXECUTED` and remains ineligible. Every mutating stage is bounded to the approved TestLab root and a named TestLab VM; cleanup is refused when the current TestId/Role marker cannot be verified, and cleanup failures remain visible and prevent an acceptance claim.

The script records Explorer correlation as `NOT_EXECUTED` unless an independent human-assisted evidence file is supplied; it never synthesizes Explorer events or marks the final acceptance eligible. It does not install Hyper-V, reboot, download ISOs, touch physical host media, or treat a workload-only run as product/privileged acceptance: the manifest remains `AcceptanceEligible=false` until the real Agent, source/canonical/state, capability, and oracle checks are independently attached.
