# Invoke-RealInstallerCase.ps1

## Role

Runs one real physical Windows installer case on behalf of `build/package/Test-Installer.ps1`. It performs the requested MSI/service/session/ACL operations and reports assertions with evidence; it is not a read-only utility.

## Ownership and invariants

Requires elevation only as a one-case child started through UAC after the non-elevated parent has presented the action and the user typed that case's exact phrase. Before creating case evidence or entering the mutation path, the driver connects to the fresh current-user-only named-pipe broker and checks the actual server PID, canonical `Test-Installer.ps1` command line, `-Execute`, RunId, PC, case, one-use nonce, challenge phrase, and externally reviewed hash-manifest fingerprint. Caller-supplied receipt/nonce values alone do not authorize execution; direct standalone invocation has no broker and fails closed. The driver independently hashes the manifest, current driver and selected MSI payloads before proceeding. The fixture root must be outside system/application/repository/bundle/synchronized folders; install/history paths must equal the canonical Program Files and ProgramData product locations. The driver validates the phrase delivered over the authenticated pipe grant; the following UAC consent is the second user confirmation. It verifies run-owned product/service state before repair/update/rollback/uninstall and checks prior case results before reinstall/retention cases.

The owner receipt is not an OS sandbox: Windows Installer may affect global installer state, Program Files, ProgramData, SCM, registry and ACL state described before UAC. The script never deletes product history. ACL fixture cleanup is restricted to the exact newly created empty child after ACL restoration; failure preserves that child/evidence. Evidence/results use `CreateNew`; no existing output is replaced. UAC cancellation must be recorded as `NOT_EXECUTED` by the parent and must not launch `msiexec`. `Invoke-Captured` records when its observation deadline expires but never kills the child; it retains the exact process handle until that child exits, returns the real exit code with `TimedOut = true`, and the current case fails without proceeding to dependent operations. A timeout is not a pass or rollback proof. MSI effects are not reversible in the general case, so this script must never be run on a normal user PC.

## Dependencies, failures, and tests

Depends on Windows Installer, SCM, ACL, interactive-session tools, and its non-elevated parent harness. Missing/mismatched broker, pipe process identity, grant, markers, host, volume, nonce, hashes, expected preceding case, or owned product/service fail closed. Static and isolated protocol tests live in `tests/StorageChronicle.Installer.Tests/InstallerManifestTests.cs`; parser/protocol tests do not establish UAC UI behavior or OS-side effect safety. The script's current-file hash check occurs after PowerShell has loaded its code, so script hash-to-load binding is not established. MSI is reopened by path after the preflight hash check, so MSI hash-to-use replacement remains unresolved. UAC execution, complete static audit, independent runtime write audit, and explicit dedicated-PC preparation remain pending; do not execute.
