# MediaImport.cs

Implements confirmed-history import from every writer directory on a media root and persists the PC-side deduplication ledger with an atomic temporary-file replacement. Media reads use a non-creating store, so importing an unknown or read-only medium does not initialize or mutate its log directory. Imports validate manifests and segments through `ExternalMediaStore`, skip already-known segment hashes, detect multiple writer PCs, report unavailable parents/corrupt segments, and apply the media-only filter before returning events.

The ledger accepts only the known object schema (`schemaVersion` 1, when present, and all three string-array fields); legacy documents without the version field remain readable. Duplicate, missing, unknown, malformed, or unsupported fields fail closed with `InvalidDataException`. Every JSON leaf in the dedicated ledger directory is validated before a save, and an existing destination is read and validated before replacement, so an unknown/corrupt file is never treated as an empty ledger or overwritten. Hash collections require valid SHA-256 values; branch identities must be nonempty bounded strings. An absent ledger returns an empty ledger. A single valid GUID-named interrupted replacement is promoted only when the destination is absent; multiple pending files, malformed pending data, or a destination/pending-file collision remain untouched and fail closed. Saves use a unique temporary file and atomic move; write failures clean up only the temporary file created by that call.

The importer does not rewrite media history or infer missing events. A corrupt or missing segment produces an honest warning and `UnverifiedGap`; cancellation propagates from directory enumeration and file reads. Tests cover PC-A to PC-B handoff, same-event/segment deduplication, branch inputs, valid interrupted-ledger recovery, missing arrays, unknown fields and leaves, malformed JSON, unsupported schema, no-overwrite preservation, and ledger reload.
