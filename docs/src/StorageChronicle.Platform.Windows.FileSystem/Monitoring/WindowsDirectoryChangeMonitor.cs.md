# WindowsDirectoryChangeMonitor

Runs the event-driven ReadDirectoryChangesW loop for one mounted root with subtree notifications enabled, so normal monitoring does not perform periodic full scans. Its producer/consumer handoff is bounded to one `DirectoryChangeRead` and waits rather than dropping source data. Native overflow (`ERROR_NOTIFY_ENUM_DIR`), malformed buffers, access denial, invalid handles, path loss, and device removal produce `ContinuityGap` with `UnverifiedGap` handling upstream. Early reader disposal cancels the producer and any outstanding native read, while terminal gap writes observe cancellation so shutdown does not wait forever on a full handoff.
