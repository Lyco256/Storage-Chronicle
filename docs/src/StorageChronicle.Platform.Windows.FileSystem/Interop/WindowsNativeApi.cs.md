# WindowsNativeApi

Implements the P/Invoke thin layer. Snapshot root metadata is read from an open handle. Descendant opens use `NtCreateFile` with `OBJECT_ATTRIBUTES.RootDirectory` set to the already-open parent directory, a single validated child-name component, and `FILE_OPEN_REPARSE_POINT`; the resulting handle is checked for the enumerated directory/file class and metadata is read from that same handle. Parent identity comes from the pinned parent handle. Child files request only `FILE_READ_ATTRIBUTES | SYNCHRONIZE`; no file-data access is requested. This prevents a renamed/replaced ancestor path from redirecting descendant opens, and observes a final reparse object without following it. Traversable root directories are opened with `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT`, verified by handle attributes, and enumerated using `GetFileInformationByHandleEx(FileIdBothDirectoryRestartInfo/FileIdBothDirectoryInfo)` on that same handle. Change-monitor directory handles additionally use `FILE_FLAG_OVERLAPPED`; each `ReadDirectoryChangesW` operation has its own event and `OVERLAPPED` storage. Cancellation calls `CancelIoEx` for that exact operation and retains its pinned buffer and native state until completion. Reparse directories are refused for both snapshot recursion and ReadDirectoryChangesW monitoring. It enumerates volume GUID paths and mount points, reads filesystem/drive/readability/USN capabilities, reads only standard metadata, and registers event-driven CM device notifications; it never reads file contents. Win32 errors are preserved for the monitor to classify as buffer loss, handle loss, removal, or access failure. Runtime guards keep non-Windows execution safe. Failures opening child components are reported by snapshot traversal as bounded continuity gaps; callers never retry through a full path.
