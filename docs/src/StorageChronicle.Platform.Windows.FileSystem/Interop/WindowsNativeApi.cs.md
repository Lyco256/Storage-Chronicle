# WindowsNativeApi

Implements the P/Invoke thin layer. Snapshot metadata opens use `FILE_FLAG_OPEN_REPARSE_POINT` and read attributes, standard information, and file identity from the resulting handle, so the final path component is observed as the link/reparse object rather than followed. Traversable directories are opened with `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT`, verified by handle attributes, and enumerated using `GetFileInformationByHandleEx(FileIdBothDirectoryRestartInfo/FileIdBothDirectoryInfo)` on that same handle. A path replaced after open cannot redirect the directory enumeration. Reparse directories are refused for both snapshot recursion and ReadDirectoryChangesW monitoring. It enumerates volume GUID paths and mount points, reads filesystem/drive/readability/USN capabilities, reads only standard metadata, and registers event-driven CM device notifications; it never reads file contents. Win32 errors are preserved for the monitor to classify as buffer loss, handle loss, removal, or access failure. Runtime guards keep non-Windows execution safe. Windows still resolves parent components of a full path; a parent-component reparse swap between path construction and opening is not closed by this path-based native contract and requires a relative-handle design.
