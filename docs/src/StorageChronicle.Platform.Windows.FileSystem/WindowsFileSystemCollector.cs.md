# WindowsFileSystemCollector

Coordinates volume enumeration, initial snapshots, and per-volume event-driven directory monitors. It uses the direct volume-GUID root rather than a mount-point alias when available, so a mounted-folder reparse point is not traversed as the volume root. The output, native-read, and live-read channels are bounded by `PipelineChannelCapacity` and use wait-mode backpressure rather than dropping events. The monitor's producer/reader handoff is also bounded to one read. Backpressure reaches ReadDirectoryChangesW; if Windows reports source-buffer loss, it is delivered as an `UnverifiedGap`. The separate initial-scan notification buffer has its own explicit capacity; exceeding it retains already-buffered items and adds an `UnverifiedGap` instead of claiming continuity. Volumes are isolated so access denied, removal, and I/O failures do not stop other volumes; linked cancellation releases blocked writers and monitor reads. Exclusion policy runs before source events are created. Native handle opening blocks final-component reparse roots, but ancestors in child paths remain subject to Windows path resolution. Tests cover success under capacity-one backpressure, native overflow reporting, volume isolation/recovery, and early-consumer cancellation.
