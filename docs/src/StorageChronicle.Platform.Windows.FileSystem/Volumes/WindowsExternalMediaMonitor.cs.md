# WindowsExternalMediaMonitor

Wraps the native Configuration Manager callback as an asynchronous stream of `ExternalMediaChange` records, without polling. Its bounded queue accepts at most the configured number of ordinary connection events (default 256; valid range 1–65,536) and reserves one additional channel slot for `ExternalMediaChangeKind.RescanRequired`.

The callback performs a short serialized queue/state transition using non-waiting `TryWrite`; it never awaits or waits for channel capacity. Once ordinary capacity is exhausted, the monitor queues exactly one reserved rescan-required record and coalesces subsequent arrivals/removals until that marker is consumed. This explicitly communicates that individual device changes may have been lost and the current volume set must be reconciled. Consuming the marker clears the overflow state, allowing later notifications through. Cancellation stops only that reader and leaves queued events available to a later enumeration; disposal unregisters the callback and completes the stream.

The public type depends on `IWindowsDeviceNotificationNative` for native registration and `ExternalMediaChange`/`ExternalMediaChangeKind` from the Windows FileSystem owned contract. It does not introduce a duplicate shared event contract or access device contents. Tests cover normal delivery, capacity-one overflow and single-marker coalescing, callback return under overflow, recovery after marker consumption, and reader cancellation with queued-event preservation. Real device arrival/removal tests are not run as part of this deterministic suite.
