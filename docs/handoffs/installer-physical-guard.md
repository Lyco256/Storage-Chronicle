# Top-agent contract: physical installer authorization broker

This file is a top-agent-owned integration contract for the `feat/installer-packaging` worker. It does not authorize physical execution. Do not edit Requirement files.

## Required execution boundary

- `Run-RealMachineInstallerAcceptance.ps1` and `Test-Installer.ps1` perform host inventory and evidence preparation in an ordinary, non-elevated process. Physical execution must fail closed if the parent is already elevated or Windows UAC is disabled. Do not launch Codex or the whole orchestrator as administrator.
- Before each individual installer case, print the exact PC, RunId, case/action, MSI names and SHA-256 hashes, install/history/evidence paths, and all known OS/service/registry effects. For service recovery, disclose the exact 5s/15s/60s restart sequence and the exact registry startup value from the MSI authoring. Require the exact one-case phrase while still non-elevated.
- Only after this presentation and phrase, launch exactly one case through Windows `runas`/UAC. The elevated driver must not be allowed to execute the mutation switch without a broker grant. UAC cancellation is `NOT_EXECUTED`; it must not create case evidence, invoke `msiexec`, or start a later dependent case in parallel.
- Create a fresh per-case `NamedPipeServerStream` with a cryptographically random name and an explicit `PipeSecurity` DACL granting read/write only to the current user's SID before launching the driver. Do not depend on `PipeOptions.CurrentUserOnly`: the target Windows PowerShell 5.1 runtime (.NET Framework) on this host does not expose that enum value. Use `NamedPipeServerStreamAcl.Create`; pass `PipeAccessRights` additionalAccessRights as zero (adding `ReadWrite` there produced `ERROR_INVALID_PARAMETER` in a non-mutating local test; read/write is already controlled by the DACL). The elevated driver receives the pipe name and parent PID. It must connect to this live broker; a missing, stale, replayed, mismatched, or caller-created receipt/nonce alone is never authorization.
- Wire format is one UTF-8 JSON object per newline. Driver first sends `StorageChronicle.InstallerCaseAuthorizationHello.v1` with `RunId`, `CaseId`, `ComputerName`, `ProcessId`, `ParentProcessId`, `AuthorizationNonce`, and `HashManifestSha256`. Parent verifies all fields and the kernel-reported pipe client PID equals the `runas` process PID. Parent then sends one `StorageChronicle.InstallerCaseAuthorizationGrant.v1` object with `RunId`, `CaseId`, `ComputerName`, `ParentProcessId`, `AuthorizationNonce`, `HashManifestSha256`, `CaseAuthorizationPhrase`, and `GrantedUtc`. Driver verifies all fields exactly and the kernel-reported server PID equals the broker PID before it can create result/evidence files. The pipe is one-connection, one-case, disposed on every exit path.
- The driver obtains the actual named-pipe server PID with `GetNamedPipeServerProcessId` and verifies it equals the broker PID. It verifies the broker's process command line identifies the canonical `Test-Installer.ps1`, `-Execute`, same RunId and PC, and rejects a directly launched driver. The parent obtains the actual pipe client PID with `GetNamedPipeClientProcessId` and compares it to the exact elevated case process returned by the UAC launch. Both sides bind the handshake to schema, PC, RunId, case ID, challenge, one-time nonce, externally reviewed hash-manifest fingerprint, and the exact payload hashes.
- The parent sends its one-time grant only after `runas` has returned the expected child and the child handshake matches. The grant carries the exact phrase that the user typed in the non-elevated parent; the driver validates it against the generated PC/RunId/case phrase before its mutation switch. The UAC consent prompt follows that disclosure and phrase, so the driver needs no interactive console or standard-input pass-through. Do not pass the phrase on the command line or treat caller-created JSON as a substitute for the live broker.
- Child results and logs are new-only, run/case-bound files. The parent reads them only after the child exits and validates schema, PC, RunId and case ID. UAC cancellation or a missing/corrupt/mismatched result is never a pass. Never terminate an elevated case child automatically on timeout; do not launch another case while one is still live.

The caller fails the current case and explicitly forbids dependent operations. Static contract coverage was updated; this does not establish Windows Installer service-side completion/rollback or authorize physical execution. Parser and targeted test results are recorded in the current integration handoff.

The driver must independently revalidate the external hash-manifest fingerprint and the exact current script/MSI payload hashes before side effects. This protocol does not solve the `msiexec` path hash-to-use race: acceptance remains **DO NOT RUN** until a separate protected staging/identity design and tests close that race. The driver script is also validated after it has already been loaded by PowerShell, so a script hash-to-load race remains. Nor does this protocol certify MSI side effects or prove that a receipt sandboxes Windows Installer.
