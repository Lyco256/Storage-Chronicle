## Required remediation before any physical product run

1. Finish the privileged runner's VHDX source-to-sink/TOCTOU review; add ownership-verified destroy only after the full run has passed, with a separate explicit confirmation, and retain all evidence.
2. Put all runner outputs beneath a user-approved evidence root outside the repository, OneDrive, Documents, existing history, and monitored data; resolve reparse points and volume identity before writes.
3. Complete the remaining installer source-to-sink and installed-state discovery review (including other/unloaded profiles), establish trusted release provenance, and independently monitor attributable writes before any explicitly user-approved dedicated-PC installer run. The automated cleanup path remains disabled; retain history and evidence.
4. Extend the history boundary to prove mapped/network volume identity and close runtime TOCTOU; review a safe migration path for any valid pre-marker history rather than adopting it implicitly.
5. The caller-settable identity boolean and path-based external-media write calls have been replaced by a handle-bound session. Before any production mirror, resolve marker authenticity (a plain schema marker is forgeable), prove ancestor-operation resistance and close remaining mount/reparse TOCTOU races, then test only on newly isolated fixtures and run a reviewed read-only host validation of the `MSFT_Partition` query. Production mirroring remains unauthorized until the code and independent audit pass.
6. Make import-ledger storage ownership-bound and append-preserving; malformed existing ledgers must be retained and surfaced as a gap rather than silently replaced from an empty ledger.
7. Complete a source-to-sink audit of collector, Agent/service, IPC, settings, storage, external media, installer, scripts, and spawned OS commands. Prove write destinations are product-owned and run corruption/recovery/abrupt-removal fault tests.
8. Implement and validate read-only host preflight plus independent process-attributed runtime write monitoring. Run static and non-privileged tests first; no normal monitored volume may be connected until both audits pass.
