# サブエージェント要件：State Engine

## ブランチ

`feat/state-engine`

## 所有パス

- `src/StorageChronicle.State/**`
- `tests/StorageChronicle.State.Tests/**`
- 対応する`docs/src/StorageChronicle.State/**`
- `docs/handoffs/state-engine.md`

## 禁止パス

共有契約、他プロジェクト、solution、Directoryファイル、Requirements。

## 目的

Canonical Eventから期間付きファイルシステム状態を更新し、任意シーケンスまたは時刻の状態、親子関係、パス、子孫を再構成する。

## 実装要件

- File ObjectとDirectory Entryを分離する。
- File ID、親ID、名前、メタデータを期間付きVersionとして持つ。
- 同名別File IDを別実体として扱う。
- フォルダー移動・名前変更はルート一件の関係変更だけを保存する。
- 子孫一件ごとの人工イベントを作らない。
- 指定時刻の祖先チェーンからフルパスを計算する。
- 移動時点の子孫集合を後から列挙できる。
- フォルダー削除前の子孫状態を保持する。
- 削除後の子孫を削除フォルダー配下に仮想表示できる。
- `ExistenceOnly`を不完全な枠として保持する。
- 親不明項目を未配置集合に保持する。
- Reconciliation Eventを通常観測と区別する。
- イベントの冪等適用を保証する。
- Source Sequence逆転、重複、欠落を検出する。
- PC時計逆行で状態順序を壊さない。
- 読取りモデルは変更不能スナップショットを返す。
- 大規模ツリー全体を一括RAM複製しない。

## テスト

- 作成、編集、名前変更、移動、削除、復元。
- フォルダー移動の全時点パス。
- 移動後に子が追加されたケース。
- 移動前の子が後から別移動したケース。
- フォルダー削除と子孫。
- 同一パス実体入替え。
- ハードリンクを完全一覧化しない状態での観測関係。
- 親不明。
- ExistenceOnly。
- 重複イベントの冪等性。
- 時計逆行。
- 100万ノード相当の合成性能テスト用fixture。

## 受け入れ条件

- フォルダー移動・削除の保存量が子孫数に比例しない。
- 任意時刻の旧新パスを正しく返す。
- 状態更新APIがUI型、Windows型、SQLite型へ依存しない。
- 単体テストと文書が完成している。
